WHAT THIS IS
------------
The game has an in-client storefront called the "Emporion of Olympus", where
players spend a soft currency called Favour on permanent account unlocks. This
file contains every item currently for sale, the metadata each item needs to be
displayed, and the display rules the game's own store front follows, so the
website can mirror it.

IMPORTANT SCOPE NOTE: the game has 12 champions but only 2 are for sale. Only
those 2 appear here. Ten other champions exist and are free to every player —
they must NOT appear in the website store. Likewise, do not invent stock: the
categories "Items" and "Cosmetics" exist in the schema but currently have
nothing for sale, and should render as empty (or be hidden — your call).

================================================================================
SECTION 1 — DATA MODEL
================================================================================

Every purchasable thing, of every kind, is one row with the same shape:

  item_id      text, primary key. Pattern: ^[a-z0-9_]{3,48}$
                  This string IS the identity of the item everywhere — ownership
                  is keyed on it. Do not rename these.
  category     one of: 'maps' | 'heroes' | 'items' | 'abilities' | 'boons'
                  | 'cosmetics'
  name         1-64 chars, display name
  description  <= 500 chars, display blurb
  icon_path    path relative to the game's public/ dir, e.g.
                  'assets/boons/hades-recall.svg'
                  Default when unset: 'assets/ui/shop-item-placeholder.png'
  cost         integer >= 0, in Favour
  is_active    boolean; false = withdrawn, hide it
  sort_order   integer; display order WITHIN a category (ascending)

Currency: "Favour" (also written "God's Favour"). Displayed as a plain
en-US thousands-separated integer, e.g. "1,250". Icon in game:
public/assets/ui/favour-placeholder.png

Category display labels and their filter-card icons (from src/types/shop.ts),
in the order they are shown:

  maps       "Maps"       assets/ui/shop-cat-maps.png
  heroes     "Heroes"     assets/ui/shop-cat-heroes.png
  items      "Items"      assets/ui/shop-cat-items.png
  abilities  "Abilities"  assets/ui/shop-cat-abilities.png
  boons      "Boons"      assets/ui/shop-cat-boons.svg
  cosmetics  "Cosmetics"  assets/ui/shop-cat-cosmetics.png

Catalogue ordering used in game: ORDER BY category ASC, sort_order ASC.

================================================================================
SECTION 4 — STORE BEHAVIOUR (to mirror the in-game panel)
================================================================================

Title of the panel: "Emporion of Olympus"

Layout: three columns — category filters (left, ~168px) | item shelf (centre,
flexible) | detail pane (right, ~250px). The shelf alone scrolls.

CATEGORY FILTERS
  - Six square cards, two per row, icon above a small label.
  - MULTI-SELECT and toggleable. Selecting none means NO filter — every category
    shows. (It does not mean an empty shelf.)
  - Changing the filter so the selected item is hidden clears the selection.

ITEM SHELF
  - A grid of square-ish tiles, auto-fill, min tile width ~112px.
  - Each tile: icon (52x52), name, cost in Favour.
  - Ordering: by category, then sort_order ascending.
  - Owned items STAY on the shelf, greyed out (grayscale + ~42% opacity), their
    price hidden, with the word "OWNED" across the bottom in green (#8fc07a).
    They remain clickable so their details can still be read.
  - Ability-unlock tiles are the only stock with a coloured border: a 2px border
    in the owning champion's colour.
  - Empty states:
      filtered to nothing -> "No offerings in the chosen categories."
      nothing at all      -> "The Emporion has no offerings yet. New stock will
                              appear here."

DETAIL PANE (right)
  - Nothing selected -> "Select an offering to inspect it." (italic, muted)
  - Selected -> large icon (84x84), name, category label in small-caps, the
    description, then "<cost> Favour", then "Already yours" if owned.
  - Prefix lines by category, as described in 2.3 and 2.4 above.

PURCHASE
  - Purchase button is enabled only when an unowned, affordable item is
    selected. Tooltips: "Select an offering first" / "You already own this
    offering" / "Not enough Favour" / "Purchase <name>".
  - Confirmation dialog text:
      "Are you sure you wish to purchase <name> for <cost> favour?"
    with the number in gold. Buttons "Purchase" / "Cancel".
  - Success message: "<name> is yours."
  - Every item is a one-time permanent unlock. Nothing is consumable, nothing
    is stackable, nothing expires.

If the website is browse-only (no logged-in purchasing), drop the purchase
button, the owned-greying and the confirm dialog; everything else still applies.
